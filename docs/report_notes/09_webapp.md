## หลักการออกแบบ

1. **แยกส่วน DE ออกจากหน้าเว็บ:** หน้าเว็บเรียกฟังก์ชันใน `pipeline/` แล้วแสดงผลเท่านั้น ไม่มีตรรกะ DE ในหน้าเว็บ (เปลี่ยนเป็น Flask ภายหลังได้)
2. **แหล่งข้อมูล:** หน้าขั้นตอน (①–④) เรียกฟังก์ชันใน pipeline เพื่อแสดงผลระหว่างทาง / หน้าผลลัพธ์ (⑤ ขึ้นไป) **อ่านจาก SQLite** ตามลำดับ ETL ใน Ch1 (Load → Data repository → Analytics)
3. **ไม่เขียนตัวเลขตายตัว:** ตัวเลขและข้อสรุปทุกจุดดึงจากผลจริง ข้อมูลเปลี่ยน (เช่น อัปโหลดไฟล์ใหม่) หน้าเว็บอัปเดตเอง
4. **Cache:** Streamlit รันโค้ดใหม่ทุกครั้งที่ผู้ใช้คลิก จึงเก็บผลไว้ (`st.cache_resource` / `st.cache_data`) คำนวณครั้งแรกครั้งเดียว และใช้ `cache_resource` ซึ่งไม่คัดลอกข้อมูลซ้ำ เพื่อประหยัดหน่วยความจำ **เมื่อฐานข้อมูลเปลี่ยน cache จะหมดอายุเอง** (ใช้เวลาแก้ไขไฟล์เป็นกุญแจ)

## ฟังก์ชันพิเศษ

**🔄 รัน pipeline ใหม่ (แถบด้านซ้าย):** รันโมดูล 2 → 8 ครบทุกขั้นพร้อมแถบความคืบหน้าทีละขั้น แสดงว่า pipeline ทำงานจริงตั้งแต่ต้นจนจบ ไม่ใช่แค่แสดงผลที่เตรียมไว้

**📤 อัปโหลดไฟล์ใหม่:** อัปโหลดไฟล์ขาย 3 สาขา + สมาชิก → **ตรวจไฟล์ก่อนรัน** (คอลัมน์ครบไหม อ่านไฟล์ได้ไหม ถ้าผิดแจ้งเป็นภาษาไทย) → รัน pipeline ลง**ฐานข้อมูลแยก** (ไม่ทับข้อมูลตัวอย่าง) → สลับชุดข้อมูลได้ที่แถบด้านซ้าย
- ถ้ารัน pipeline ล้มเหลวกลางทาง ระบบ**ลบไฟล์และฐานข้อมูลที่ค้างทิ้ง**และกลับไปใช้ข้อมูลตัวอย่าง ไม่เหลือชุดข้อมูลที่ใช้ไม่ได้ให้เลือก
- **ข้อจำกัด:** ไฟล์ต้องเป็นข้อมูลช่วง ม.ค.–มิ.ย. 2569 เพราะกฎคุณภาพ (ช่วงวันที่) และการแบ่งข้อมูลของโมเดล (ฝึก/ทดสอบตามเดือน) กำหนดช่วงนี้ไว้ ถ้าจะรองรับช่วงอื่นต้องทำให้ค่าเหล่านี้คำนวณจากข้อมูลแทน (แนวทางพัฒนา)

**ช่องพิมพ์ SQL (หน้า ⑤):** ปลอดภัย 3 ชั้น
1. รับเฉพาะคำสั่งเดียวที่ขึ้นต้นด้วย `SELECT` หรือ `WITH`
2. ปฏิเสธคำที่ใช้แก้ข้อมูล (`INSERT`, `UPDATE`, `DELETE`, `DROP`, `PRAGMA` ฯลฯ)
3. **เปิดฐานข้อมูลแบบอ่านอย่างเดียว** (`mode=ro`) ถึงหลุดสองชั้นแรกก็แก้ข้อมูลไม่ได้ (มี test ยืนยัน)

## การทดสอบ

`tests/test_app.py` ใช้ `streamlit.testing` (เครื่องมือทดสอบของ Streamlit เอง) **รัน pipeline ทั้งสายลงฐานข้อมูลชั่วคราว แล้วเปิดทุกหน้า** (ทดสอบการทำงานต่อกันทั้งสาย ตามบทเรียนจากโมดูล 6–7)
- ทุกหน้า (9 หน้า) และไฟล์หลักเปิดได้โดยไม่มี error
- เลือกเมนูในหน้า Recommendation แล้วได้คำแนะนำถูกต้อง / กรองสาขาใน Dashboard ได้
- ช่อง SQL ปฏิเสธคำสั่งแก้ข้อมูลทุกแบบ และข้อมูลยังอยู่ครบ
- ไฟล์อัปโหลดที่ถูกต้องผ่าน / ไฟล์ผิด (คอลัมน์ไม่ครบ, อ่านไม่ได้) ถูกปฏิเสธ / อัปโหลดแล้วรันทั้งสายได้โดยไม่ทับข้อมูลตัวอย่าง
- **กรณีสุดขอบ:** เลือกเมนู 0 / 1 / 13 / 14 / ครบ 15 เมนู, เลือกเดือนเดียว, ไม่เลือกสาขา, สลับทีละสาขา, SQL ตัวอย่างทุกข้อ
- **ตารางต้องไม่มีคอลัมน์ที่ปนตัวเลขกับข้อความ** (ดักข้อความเตือนของตัวแปลงตาราง Arrow ใน log ทุกหน้า และกดทุกปุ่ม)
- เปิดแอปครั้งแรกโดยยังไม่มีฐานข้อมูล (เหมือนเพิ่ง clone โปรเจกต์) ต้องรัน pipeline ให้อัตโนมัติ
- หน้าเว็บไม่อ่านไฟล์เฉลย

**ปัญหาที่เจอระหว่างพัฒนา:** Streamlit แจ้งว่าคำสั่ง `use_container_width` จะถูกยกเลิก จึงเปลี่ยนเป็น `width="stretch"` ทุกจุด กันไม่ให้แอปพังถ้าอาจารย์ใช้ Streamlit เวอร์ชันใหม่กว่า

**ปัญหาที่เจอตอนตรวจทาน (แก้แล้ว):**
1. ตาราง Load verification มีคอลัมน์ที่ปนตัวเลขกับข้อความ ทำให้เกิด error ใน log (หน้าเว็บยังแสดงได้ แต่ดูไม่ดีตอน Demo) เจอจากการอ่าน log ของหน้าเว็บที่เปิดใช้งานจริง
2. เลือกเมนูครบทั้ง 15 เมนูในหน้า Recommendation แล้วหน้าเว็บ error เพราะไม่มีเมนูเหลือให้แนะนำ เจอจากการทดลองกรณีสุดขอบ
3. ถ้ารัน pipeline กับไฟล์ที่อัปโหลดแล้วล้มเหลว จะเหลือฐานข้อมูลที่สร้างไม่เสร็จให้เลือก ทำให้ทุกหน้า error

บทเรียน: tests ที่ตรวจแค่ "หน้าเปิดได้ไหม" ไม่พอ ต้องดู log และลองกรณีสุดขอบด้วย

ตอบ: ทั้งสองแบบ หน้าขั้นตอนเรียกฟังก์ชันใน pipeline จริง และมีปุ่มรัน pipeline ใหม่ทั้งสาย หรืออัปโหลดไฟล์ใหม่แล้วรันได้ ส่วนหน้าผลลัพธ์อ่านจากฐานข้อมูลตามลำดับ ETL

**ถาม: ถ้าอัปโหลดไฟล์ผิดรูปแบบจะเกิดอะไร**
ตอบ: ระบบตรวจไฟล์ก่อนรัน ถ้าคอลัมน์ไม่ครบหรืออ่านไฟล์ไม่ได้ จะแจ้งเป็นภาษาไทยว่าไฟล์ไหนผิดอะไร ไม่รัน pipeline และไม่ทับข้อมูลเดิม

**ถาม: ช่องพิมพ์ SQL อันตรายไหม**
ตอบ: ป้องกัน 3 ชั้น ชั้นสุดท้ายคือเปิดฐานข้อมูลแบบอ่านอย่างเดียว ต่อให้พิมพ์คำสั่งลบข้อมูลก็ทำไม่ได้ มี test ยืนยัน

**ถาม: ทำไมใช้ Streamlit ไม่ใช้ Google Data Studio**
ตอบ: Streamlit เป็น Python เหมือน pipeline จึงเรียกใช้ฟังก์ชันได้โดยตรง แสดงได้ทั้งขั้นตอน DE ระหว่างทาง รันใหม่ได้ อัปโหลดไฟล์ได้ และมีโมเดลให้ลองใช้ ซึ่ง Data Studio ทำไม่ได้ ส่วน Dashboard ทำหน้าที่เหมือน Data Studio
