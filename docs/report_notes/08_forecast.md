## ภาพรวม

ทำนาย **"แต่ละสาขาจะขายได้กี่บาทในแต่ละวัน"** เพื่อช่วยร้านวางแผนสั่งวัตถุดิบและจัดคน ด้วย **Linear Regression** เพราะอธิบายได้ทุกตัวเลข

**เป็นโมเดลโบนัส (นอกเนื้อหาวิชา)** ส่วนที่เชื่อมกับวิชา:
- ใช้ตัวแปรที่ทำ **One-hot / Dummy encoding และ Z-score** ไว้ในโมดูล 5 (Ch2, Lab 4)
- Linear Regression ตัวเดียวกับ **Regression imputation** ในโมดูล 4 (Ch4)
- สร้างตัวแปร วันหยุด × สาขา = **Attribute construction** (Ch2)
- วิเคราะห์ความคลาดเคลื่อนด้วย Line chart / Histogram (Ch6)

## หลักการ

```
ยอดขายวันนี้ ≈ ยอดตั้งต้นของสาขา           (One-hot สาขา 3 ตัว แทนค่าคงที่)
            + ผลของวันธรรมดา               (Dummy อังคาร–ศุกร์ เทียบกับวันจันทร์)
            + ผลของเสาร์-อาทิตย์ แยกสาขา
            + ผลของวันหยุด แยกสาขา
            + น้ำหนัก × ยอดวันเดียวกันของสัปดาห์ก่อน (Z-score)
            + น้ำหนัก × แนวโน้มตามเวลา            (Z-score)
```
Linear Regression หาตัวเลขแต่ละบรรทัด (coefficient) ที่ทำให้ผลรวมของความคลาดเคลื่อนยกกำลังสองน้อยที่สุด (Least squares)

**ป้องกัน Dummy variable trap:**
- ไม่ใส่ค่าคงที่ (`fit_intercept=False`) เพราะ One-hot สาขา 3 คอลัมน์รวมกันได้ 1 เสมอ
- วันหยุดแยกสาขา 3 ตัวใช้**แทน**ตัวแปรวันหยุดรวม (ถ้าใส่ทั้งคู่ ผลรวมของ 3 ตัวจะเท่ากับตัวแปรรวมพอดี)
- เสาร์-อาทิตย์แยกสาขาใช้**แทน** dummy วันเสาร์ / วันอาทิตย์
- **มี test ตรวจ**ว่าตัวแปรไม่ซ้ำซ้อน (เมทริกซ์ full rank)
- หมายเหตุ: ตอนวางแผนผมลองตัวแปรแยกสาขาแบบคร่าว ๆ โดยใส่ซ้อนกับตัวแปรรวม ซึ่งเกิด Dummy variable trap ตัวเลขชุดนั้นจึงใช้ไม่ได้ ตอนเขียนจริงแก้แล้วตามข้างบน

## การกัน Data leakage (ข้อมูลอนาคตรั่วเข้าโมเดล)

| วิธี | ทำอย่างไร | ทำไม |
|---|---|---|
| **แบ่งตามเวลา 3 ชุด** | ฝึก ม.ค.–เม.ย. / **เลือกโมเดลด้วย พ.ค.** / ทดสอบ มิ.ย. ครั้งเดียว | ถ้าเลือกโมเดลจากชุดทดสอบ = แอบดูข้อสอบ ตัวเลขจะดีเกินจริง |
| **Z-score จากข้อมูลฝึกเท่านั้น** | ค่าเฉลี่ยและ SD คำนวณจากช่วงฝึก แล้วนำไปใช้กับช่วงทดสอบ | ถ้าใช้ทั้ง 6 เดือน โมเดลจะแอบเห็นข้อมูลเดือน มิ.ย. (เรื่องที่แจ้งไว้ในโมดูล 5) |
| **ใช้เฉพาะข้อมูลที่รู้ล่วงหน้า** | ยอด 7 วันก่อน, วันในสัปดาห์, วันหยุด, ลำดับวัน | ไม่ใช้จำนวนบิลของวันนั้น เพราะตอนทำนายยังไม่รู้ |
| **ไม่ใช้วันที่ข้อมูลหาย** | ท่าแพ 3 วันไม่อยู่ในข้อมูลฝึก | ไม่ให้โมเดลเรียนว่า "บางวันขายไม่ได้เลย" |

**มี tests ตรวจทั้ง 4 ข้อ** เช่น เปลี่ยนยอดขายเดือน มิ.ย. เป็นค่าสุ่ม แล้วตรวจว่าการเลือกโมเดลยังได้ผลเดิม และเปลี่ยนยอดเดือน พ.ค.–มิ.ย. แล้วตรวจว่าผล Walk-forward ของเดือน เม.ย. ไม่เปลี่ยน

**ตรวจความถูกต้องด้วยวิธีอื่น:** สร้างข้อมูลใหม่จาก `agg_daily` ด้วย SQL แล้วแก้สมการ Least squares เองด้วย numpy ได้ Coefficient และตัวเลขความคลาดเคลื่อนตรงกับโมดูลนี้ทุกค่า

## วิเคราะห์ความคลาดเคลื่อน: ทำไมแพ้ในเดือน มิ.ย. ⭐

**ความคลาดเคลื่อนแยกสาขา (มิ.ย.)**
| สาขา | MAE | ทายเฉลี่ยต่ำไป | ยอดเฉลี่ยจริง |
|---|---|---|---|
| **มช.** | **1,170** | **−1,169 บาท/วัน** | 2,182 |
| นิมมาน | 704 | −464 | 2,877 |
| ท่าแพ | 410 | −13 | 1,577 |

**มช. ถูกทายต่ำเกินไปทุกสัปดาห์ของเดือน มิ.ย.** (−1,096 / −1,471 / −1,157 / −1,094 / −666 บาท)

**สาเหตุ: มช. เปิดเทอมวันที่ 1 มิ.ย.**
```
ยอดเฉลี่ยต่อวันของ มช.:  ม.ค. 2,348 → ก.พ. 2,380 → มี.ค. 1,609 → เม.ย. 732 → พ.ค. 818 → มิ.ย. 2,182
                                                   └──────── ปิดเทอม ────────┘   └ เปิดเทอม ┘
```
1. **โมเดลไม่มีข้อมูลว่า มช. ปิดหรือเปิดเทอม** จึงเรียนจากข้อมูลฝึกที่มีช่วงปิดเทอมอยู่ 2 เดือนครึ่ง แล้วคิดว่ายอดของ มช. ต่ำเป็นปกติ
2. **ตัวแปรแนวโน้มเวลาเรียนว่ายอดลดลงวันละ 6.7 บาท** (เพราะ ม.ค.–พ.ค. ยอดรวมลดลงจากปิดเทอมและท่าแพหมด high season) แล้ว**ลากแนวโน้มนี้ต่อไปในเดือน มิ.ย.** ทำให้นิมมานถูกทายต่ำด้วย (ปลายเดือนต่ำไปถึง 1,000 บาท/วัน)
3. ยอดสัปดาห์ก่อน (lag7) มีน้ำหนักน้อย (0.18 บาทต่อ 1 บาท) โมเดลจึงปรับตามสถานการณ์ใหม่ได้ช้า

**บทเรียน:** โมเดลที่เรียนจากอดีตจะพลาดเมื่อ**สถานการณ์เปลี่ยนกะทันหัน** และไม่มีตัวแปรที่บอกการเปลี่ยนแปลงนั้น การดูแค่คะแนนรวม (MAE) ไม่พอ ต้องวิเคราะห์ความคลาดเคลื่อนแยกกลุ่ม (สาขา, สัปดาห์) จึงเห็นต้นเหตุ

**ทดลองแก้ด้วยการเลือกตัวแปรแล้ว แต่ไม่ได้ผล:** ถ้าตัดตัวแปรแนวโน้มออก เดือน มิ.ย. ดีขึ้น (642 บาท) แต่ เม.ย. และ พ.ค. แย่ลง ไม่มีรุ่นไหนดีทุกเดือน เพราะปัญหาจริงคือ**ขาดข้อมูล** ไม่ใช่การเลือกตัวแปร และ**เราไม่เปลี่ยนโมเดลตามผลเดือน มิ.ย.** เพราะจะเท่ากับแอบดูข้อสอบ

ตอบ: เดือน มิ.ย. เป็นข้อมูลทดสอบ ถ้าปรับโมเดลจนชนะในเดือนนี้ เท่ากับแอบดูข้อสอบ ตัวเลขจะหลอกตัวเอง เราจึงรายงานตามจริงและเสนอแนวทางแก้ที่ต้นเหตุ (เพิ่มข้อมูลปฏิทินการศึกษา)

**ถาม: Data leakage คืออะไร ป้องกันอย่างไร**
ตอบ: คือการที่ข้อมูลอนาคตรั่วเข้าโมเดลตอนฝึก ทำให้ผลทดสอบดีเกินจริง เราป้องกัน 4 ทาง: แบ่งตามเวลา, เลือกโมเดลด้วยเดือน พ.ค. ไม่ใช่ มิ.ย., คำนวณ Z-score จากข้อมูลฝึกเท่านั้น และใช้เฉพาะตัวแปรที่รู้ล่วงหน้า มี tests ตรวจทุกข้อ

**ถาม: ทำไมไม่ใส่ค่าคงที่ในโมเดล**
ตอบ: ตัวแปรสาขา 3 คอลัมน์ (One-hot) รวมกันได้ 1 เสมอ ถ้ามีค่าคงที่ด้วยจะซ้ำซ้อนกัน (Dummy variable trap) โมเดลจะหาค่าที่แน่นอนไม่ได้ จึงให้ 3 คอลัมน์สาขาทำหน้าที่เป็นยอดตั้งต้นของแต่ละสาขาแทน อ่านผลง่ายกว่าด้วย

**ถาม: ทำไมไม่ใช้โมเดลที่ซับซ้อนกว่านี้**
ตอบ: ปัญหาหลักคือขาดข้อมูล ไม่ใช่โมเดลไม่ซับซ้อนพอ โมเดลที่ซับซ้อนกว่าก็ไม่รู้ว่า มช. เปิดเทอม และจะอธิบายผลยากขึ้น Linear Regression อธิบายได้ทุกตัวเลข ร้านนำไปใช้ตัดสินใจได้
