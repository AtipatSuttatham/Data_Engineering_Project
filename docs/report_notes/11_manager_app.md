# Doi Brew Manager: หน้าเว็บสำหรับใช้งานจริง (บันทึกสำหรับเล่มและการนำเสนอ)

> รัน: `python -m streamlit run manager_app.py --server.port 8502 --theme.primaryColor "#1B1916"` แล้วเปิด **http://localhost:8502**
> โค้ด: `manager_app.py` (เมนูด้านบน + แถบตัวเลือก) / `manager/steps.py` (รายละเอียดขั้นตอน ①–⑤) / `manager/insights.py` (คำนวณตัวเลข, pandas ล้วน) / `manager/importer.py` (นำเข้าไฟล์ เรียก pipeline/) / `manager/theme.py` (สีและกราฟ) / `manager/pages/` (4 หน้า)

## ต่างจากหน้าเว็บเดิม (app.py) อย่างไร

| | หน้าเว็บเดิม (โมดูล 9) | Doi Brew Manager |
|---|---|---|
| ผู้ใช้ | อาจารย์ / ผู้ฟังการนำเสนอ | เจ้าของร้าน / ผู้จัดการสาขา |
| เมนู | 9 หน้า เรียงตามขั้นตอน pipeline | 4 หน้า: อัปโหลดไฟล์ / ภาพรวม / แดชบอร์ด / คาดการณ์ |
| ขั้นตอน ①–⑤ | หน้าละ 1 ขั้น | อยู่ใต้หน้าอัปโหลดไฟล์ เป็นกล่องกดเปิด-ปิด (หัวกล่องมีสรุปผลสั้น ๆ) + สวิตช์เปิดทั้งหมด |
| บอกเทคนิค | อธิบายยาวในหน้า | ป้ายเล็กบนการ์ด เช่น `Ch6 · Moving average` (ปิดได้) |
| Recommendation | มี | ไม่มี (ยังคำนวณใน pipeline และแสดงในหน้าเว็บเดิม) |

ใช้ฐานข้อมูลและฟังก์ชันใน `pipeline/` ตัวเดียวกัน ไม่มีตรรกะ DE ใหม่ ไม่แก้ไฟล์ของหน้าเว็บเดิม และไม่เขียนตัวเลขตายตัว

## การนำเข้าไฟล์ (Input → Process → Output)

อัปโหลดหลายไฟล์พร้อมกัน (CSV / Excel / JSON) → `insights.detect_kind` ดูชื่อคอลัมน์แล้วบอกว่าเป็นไฟล์ของสาขาไหน หรือขาดคอลัมน์อะไร → กด "ประมวลผลและโหลด" → `extract` + `clean.run_clean` (วัดคุณภาพและทำความสะอาด) → `transform` → `load.run_load` (Full refresh ลงฐานข้อมูลแยกของชุด "ข้อมูลที่อัปโหลด") → โมเดลคำนวณใหม่ → แสดงผล Load verification แล้วทุกหน้าสลับไปแสดงข้อมูลชุดนี้ (สลับกลับได้ที่แถบบนสุด)

**ทำไมใช้ Full refresh ไม่ใช้ Incremental load กับไฟล์ที่อัปโหลด:** การทำความสะอาด (Z-score, การเติมค่าด้วย Regression) และตารางสรุปคำนวณจากข้อมูลทั้งชุด ถ้าเพิ่มทีละส่วน ตัวเลขของข้อมูลเดิมจะไม่ถูกคำนวณใหม่ ส่วน Incremental load ยังสาธิตได้ในขั้น ⑤

**ข้อจำกัด (บอกบนหน้าเว็บ):** ไฟล์ต้องเป็นข้อมูลช่วง ม.ค.–มิ.ย. 2569 และต้องมีครบ 4 ไฟล์ (ยอดขาย 3 สาขา + สมาชิก)

## คำถามที่อาจารย์อาจถาม

**ถาม: ทำไมมีหน้าเว็บ 2 ตัว**
ตอบ: ตัวเดิมเล่าขั้นตอน DE สำหรับการนำเสนอ ตัวใหม่จัดหน้าตามงานของผู้ใช้จริง และย้ายขั้นตอน ①–⑤ มาไว้เป็นรายละเอียดที่เปิดดูได้ เรียกฟังก์ชันใน `pipeline/` ชุดเดียวกัน จึงเห็นว่า pipeline นำไปใช้งานจริงได้

**ถาม: ระบบรู้ได้อย่างไรว่าไฟล์เป็นของสาขาไหน**
ตอบ: ดูนามสกุลและชื่อคอลัมน์ (Data discovery) เทียบกับคอลัมน์ที่ Schema mapping ของแต่ละสาขาต้องใช้ ถ้าขาดคอลัมน์จะบอกชื่อคอลัมน์ที่ขาด ไม่รัน pipeline

**ถาม: ป้ายเทคนิคบนการ์ดมีไว้ทำอะไร**
ตอบ: บอกว่าตัวเลขหรือกราฟนั้นมาจากเทคนิคบทไหน ตามเกณฑ์ที่ต้องระบุที่มาของทุกเทคนิค ปิดได้เมื่อใช้งานจริง
